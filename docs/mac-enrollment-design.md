# macOS host enrollment — design

> Extends `kvasir enroll-host` to support Apple Silicon macOS targets
> (currently `odin` and `skoll`). Companion document to
> `freeipa-fleet-enrollment-recipe.md` (Linux recipe), which this design
> mirrors as closely as the macOS identity stack allows.

## Goal

`kvasir enroll-host odin --apply` (and `kvasir enroll-host skoll --apply`)
should leave the target macOS host with:

1. **Identity from FreeIPA.** `id nwalker`, `dscl . -read /Users/nwalker`,
   and `getent passwd nwalker` all resolve to the canonical FreeIPA UID/GID.
2. **Kerberos SSO.** Host keytab installed at `/etc/krb5.keytab`;
   `/etc/krb5.conf` configured for the `RAVENHELM.DEV` realm; `kinit nwalker`
   works from the target.
3. **Sudo, rendered from IPA at enrollment time.** A
   `/etc/sudoers.d/kvasir-managed-<short>` fragment on the target,
   regenerated by kvasir from the IPA sudo rule `kvasir-root-<short>` on
   each enroll-host run, grants `nwalker` passwordless root. Note: IPA
   rules are not consulted at sudo invocation time on macOS — re-run
   kvasir to sync changes. See Non-goals.
4. **1Password record.** `FreeIPA Host <short>` item in the `ravenmask`
   vault, matching the Linux convention.

Existing local users (`ravenhelm@odin`, `nate@skoll`) are **untouched** and
remain as break-glass admins. No GUI login window changes; no mobile
accounts; no FileVault interaction.

## Non-goals

- Mobile accounts / Apple loginwindow integration (out of scope by choice;
  Macs continue to log in as local users at the GUI).
- IPA HBAC enforcement on macOS (Apple's auth stack doesn't honor it;
  sudoers fragment is the documented workaround).
- SSSD on macOS (Homebrew package exists but is volunteer-maintained and
  brittle across macOS major versions — see Approaches Considered).
- Automatic sudoers re-sync on a timer (kvasir is run-on-demand; re-run
  to pick up rule changes).
- macOS major version upgrade survival — out of scope; document in runbook.

## Approaches considered

### A — Apple-native Directory Services + Heimdal Kerberos *(chosen)*

Bind macOS to FreeIPA's LDAP interface via `/Library/Preferences/OpenDirectory/Configurations/LDAPv3/<server>.plist`
written directly (bypassing `dsconfigldap`'s GUI hooks), reload
`opendirectoryd`, configure `/etc/krb5.conf` for the realm, install the
host keytab from `ipa-getkeytab`.

- **Pro:** Built-in macOS components; no third-party packages; survives
  macOS updates better than alternatives.
- **Pro:** `id`, `dscl`, `getent`, `kinit` all just work after binding.
- **Pro:** Kerberos integration via Apple's well-tested Heimdal kpath.
- **Con:** `dsconfigldap` CLI has rough edges (interactive bind dialog in
  some macOS versions). Workaround: write the plist directly +
  `killall opendirectoryd`, fully scriptable.
- **Con:** Mapping template tweaks for FreeIPA (`apple-user-class` vs
  `posixAccount`) sometimes need plist edits.

### B — SSSD via Homebrew

Install `brew install sssd`, configure `/opt/homebrew/etc/sssd/sssd.conf`,
launchd daemon.

- **Pro:** Architectural parity with Linux enrollment.
- **Con:** Unofficial; volunteer-maintained; breaks on macOS major version
  bumps. Doesn't integrate with Apple's Directory Services (`dscl` and the
  GUI users panel can't see SSSD users).

### C — Kerberos auth only, no LDAP identity

Just `/etc/krb5.conf` + host keytab. Local accounts only.

- **Pro:** Smallest change.
- **Con:** `id nwalker` fails; sudoers fragment for `nwalker` would be a
  dangling reference. Doesn't meet the stated goal.

## Architecture

`kvasir enroll-host <target>` remains the single entry point. Inside
`bin/enroll-host`, after the existing target probe, branch on OS family:

- `Linux` → existing flow (untouched)
- `Darwin` → new `lib/mac.sh` flow
- anything else → existing `kvasir::die "unsupported OS"`

### File layout

```
kvasir/
├── bin/
│   └── enroll-host                        # +Darwin branch, ~10 lines
├── lib/
│   ├── freeipa.sh                         # +ipa::host_keytab() helper
│   └── mac.sh                             # NEW — Apple DS + Kerberos logic
├── tests/
│   ├── mac-enroll-host-test.sh            # NEW — pure-local unit tests
│   └── mac-enroll-host-integration-test.sh # NEW — gated by env var
└── docs/
    └── mac-enrollment-design.md           # this document
```

### Conventions preserved

- `kvasir::ssh_sudo` for all remote root ops
- `kvasir::is_dry_run` / `kvasir::log` for everything
- `kvasir::parse_common_flags` for `--apply` / `--dry-run` / `--debug`
- 1Password item naming: `FreeIPA Host <short>` (same as Linux)
- `lib/mac.sh` functions namespaced `mac::*`; internal helpers `mac::_*`

## Enrollment flow

Ten logical steps, each validated before the next:

```
[1/10]  Probe target            ssh OK, uname=Darwin, sw_vers, hostname -s, en0 IP
[2/10]  Mint host record        ipa::host_register $FQDN  (existing, reused)
[3/10]  Mint host keytab        NEW ipa::host_keytab $FQDN — runs
                                `ipa-getkeytab -p host/$FQDN -k /tmp/$FQDN.keytab`
                                in container, cats keytab to stdout (base64 transport)
[4/10]  Stage /etc/krb5.conf    write minimal realm config: default_realm,
                                [realms], [domain_realm] mapping
[5/10]  Install host keytab     decode base64 → /etc/krb5.keytab,
                                chmod 0600 root:wheel; `klist -k` to validate
[6/10]  Stage CA cert           ipa::ca_cert → /etc/openldap/cacert.pem
                                (referenced by the LDAPv3 plist for TLS bind)
[7/10]  Bind to LDAP            write LDAPv3 plist directly;
                                `dscl /Search -append / CSPSearchPath /LDAPv3/<server>`;
                                `killall opendirectoryd` (launchd respawns)
[8/10]  Validate identity       `id nwalker`, `dscl . -read /Users/nwalker UniqueID`,
                                `klist -k` shows host principal
[9/10]  Write sudoers fragment  read IPA sudo rule `kvasir-root-<short>` via
                                ipa::cmd, render to
                                /etc/sudoers.d/kvasir-managed-<short>,
                                `visudo -cf` validate before install
[10/10] Save 1P record          op::create_item "FreeIPA Host <short>"
                                with otp, fqdn, lan-ip, os=darwin,
                                kerberos=enabled, sudo-fragment-path, enrolled-at
```

Steps 1, 2, 10 reuse existing functions. Step 9 reuses `ipa::cmd
sudorule-show`. Everything else is new in `lib/mac.sh`.

### Plist template (step 7)

`lib/mac.sh` ships a hardcoded LDAPv3 plist template with placeholders for
`${KVASIR_FREEIPA_FQDN}`, `${KVASIR_FREEIPA_DOMAIN}`. RFC2307 attribute
mapping (matching FreeIPA's `cn=accounts` schema):

| Apple attribute | LDAP attribute |
|---|---|
| `RecordName` | `uid` |
| `UniqueID` | `uidNumber` |
| `PrimaryGroupID` | `gidNumber` |
| `NFSHomeDirectory` | `homeDirectory` |
| `UserShell` | `loginShell` |
| `RealName` | `cn` |
| `EMailAddress` | `mail` |
| `AuthenticationAuthority` | `;Kerberosv5;;<uid>@RAVENHELM.DEV;RAVENHELM.DEV` |

**Bind authentication.** Try anonymous bind first; this works in
FreeIPA's default ACI for `cn=accounts` when reading the attrs needed by
`id`/`dscl`. If implementation testing shows FreeIPA's ACI blocks
anonymous reads of any required attr (notably `uidNumber`/`gidNumber` on
some hardened deployments), fall back to a low-priv readonly bind DN
provisioned by kvasir during enrollment — credentials in 1Password under
`FreeIPA LDAP Read`, plist references the DN + password from disk. Decide
in implementation phase based on actual probe results. TLS required
either way (the plist sets `SSLEnabledKey=YES` and references
`/etc/openldap/cacert.pem`).

### Sudoers fragment (step 9)

Regenerated on every `kvasir enroll-host` run. Header comment:

```
# Managed by kvasir — DO NOT EDIT.
# Re-run `kvasir enroll-host <short> --apply` to sync with IPA sudo rule
# kvasir-root-<short>. Last generated: <iso-timestamp>.
nwalker ALL=(root) NOPASSWD: ALL
```

Validated via `visudo -cf` against a temp file before `install -m 0440
root:wheel` replaces the live fragment.

## Idempotency

| Step | Re-run behavior |
|---|---|
| 2 | `ipa::host_register` deletes + re-adds if exists (invalidates server-side keytab). Re-run = key rotation. |
| 3 | Always minted fresh; old keytab on target overwritten in step 5. |
| 4 | Idempotent template write. Non-kvasir content backed up to `/etc/krb5.conf.kvasir-bak.<epoch>` before overwriting. |
| 5 | `klist -k` first; if host principal already present with current kvno, log OK and skip. Otherwise overwrite. |
| 7 | Plist write is idempotent; `dscl /Search -append` deduplicated (check `CSPSearchPath` first). `killall opendirectoryd` reload. |
| 9 | Always regenerated; `visudo -cf` validates before install. Old fragment intact if validation fails. |

## Error handling

- All file mutations: temp-then-install pattern (`write to /tmp/kvasir.XXX`,
  validate, `install`). No half-written files on disk if a step fails.
- Each step's validation runs immediately. If step 5 says "host principal
  not in keytab" → die before touching LDAP bind.
- `kvasir::_on_err` trap inherited from `common.sh` prints failing line +
  exit code.
- Detection of pre-existing FreeIPA state on target: check for
  `/etc/krb5.keytab` containing a `host/...@RAVENHELM.DEV` principal AND
  existing LDAPv3 plist:
  - Both present and matching → treat as refresh (re-issue keytab,
    regenerate sudoers, log "already enrolled, refreshing")
  - Partial state → require `--force-reenroll` to proceed (prevents
    accidental corruption of half-enrolled host)

## Rollback / break-glass

- Backups: `/etc/krb5.conf.kvasir-bak.<epoch>`,
  `/etc/sudoers.d/<name>.kvasir-bak.<epoch>` — recoverable via `mv`.
- `lib/mac.sh` ships `mac::uninstall` (callable function, not yet a
  subcommand) that: deletes the LDAPv3 plist, removes it from
  `CSPSearchPath`, removes host principal from keytab via `ktutil`, deletes
  the sudoers fragment, restores backups. Existing local user
  (ravenhelm/nate) never touched — a botched bind still leaves you a
  working admin login.
- 1Password item includes `uninstall-cmd` field with the literal one-liner
  to reverse the bind, for true break-glass.

## Testing

### Unit tests (`tests/mac-enroll-host-test.sh`)

Pure-local; no SSH/IPA dependencies. Functions tested:

- `mac::_render_ldap_plist` — output passes `plutil -lint`
- `mac::_render_krb5_conf` — output contains required `[realms]`,
  `[domain_realm]`, `default_realm` sections
- `mac::_render_sudoers_fragment` — output passes `visudo -cf -` (piped)
- `mac::_should_refresh` — table-driven test of present/absent combos of
  plist + keytab principal
- `mac::_extract_sudo_options` — parses canned `ipa::cmd sudorule-show`
  output correctly (mock `ipa::cmd`)

### Integration test (`tests/mac-enroll-host-integration-test.sh`)

Gated by `KVASIR_INTEGRATION_TARGET=odin` env var; skipped in CI by
default. Runs the full flow in dry-run, optionally `--apply` if
`KVASIR_INTEGRATION_APPLY=1`, validates post-state (`id nwalker`,
`klist -k`, `sudo -n true` as nwalker), then runs `mac::uninstall` and
re-validates clean state. Documented as "run manually on a Mac you can
afford to reset."

### Validation in real runs

Step 8 hard-fails if `id nwalker` returns nonzero or UniqueID is empty.
Final block prints a checklist matching Linux enroll-host's depth:

```
✓ host principal in /etc/krb5.keytab
✓ id nwalker → uid=12345(nwalker) gid=12345(nwalker)
✓ dscl . -read /Users/nwalker UniqueID
✓ /etc/sudoers.d/kvasir-managed-odin valid
✓ 1Password item "FreeIPA Host odin" written
```

Exit non-zero on any validation failure so
`kvasir enroll-host odin --apply && echo done` is reliable.

## Rollout

1. Land code + unit tests on `feat/mac-enrollment` branch
2. Dry-run against `odin` and `skoll`; review output
3. Apply to **skoll first** (M1 MacBook, lower blast radius, `nate` local
   user stays as fallback admin)
4. Validate; live-test for 24h
5. Apply to **odin** (M4 Pro production server with services — higher
   blast radius)
6. Once both stable: open follow-up to migrate the powermetrics interim
   sudoers fragment from `ravenhelm`/`nate` to `nwalker`, remove the
   "REMOVE on FreeIPA enrollment" comment
7. Update `lab-status` memory entry to reflect that nwalker now works on
   macOS hosts
